## 🧭 How I Build

Most of what I ship lives inside banking apps, which changes how you think about every screen — a slow QR scan or a confusing eKYC step isn't a bug, it's someone losing trust in their bank. Four things guide the work:

1. **Reusable architecture over repeated patterns** — shared components and mixins so the same flow isn't rebuilt, and re-debugged, across four different bank apps
2. **Performance for real devices, not flagship benchmarks** — profiled for the lower-end Android hardware common across Bangladesh, not a best-case phone
3. **Security and observability, built in from the start** — custom interceptors for request logging and security sit in the base architecture from day one
4. **A release pipeline that catches problems before users do** — develop → unit test → QA test, with deliberate release decisions before a branch is ever finalized
